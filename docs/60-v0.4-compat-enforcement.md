# 60 — v0.4 — compat enforcement

v0.3 lets Setups declare what KOReader version and device(s) they target,
but only displays those fields on inspect/import. v0.4 turns them into a
gate: import against a device that's out of the declared window fails
loudly, not silently.

## Goal

Stop a Setup exported for one context from landing on a device it wasn't
written for. Specifically: a manifest that requires a newer KOReader
than the device runs, or targets a family the device isn't in, should
block at the import boundary before any file is touched.

## Scope decisions

| # | Question | Decision |
|---|----------|----------|
| B1 | What to detect on-device? | KOReader version from `<mount>/koreader/git-rev`; device family from the first token of `<mount>/system/version.txt` (e.g. `Kindle`, `Kobo`). |
| B2 | Version comparison? | Parse to `{year, month, patch}` tuples. Guards the lex trap (`v2024.9 < v2024.10`). |
| B3 | Device matching? | Family-level. Manifest values `kindle-pw5` or `kindle` both match detected family `kindle` — the hyphen-prefix is treated as a sub-label. |
| B4 | Detection failure? | **Soft warn, proceed.** Missing `git-rev`, missing `version.txt`, or an unparseable manifest version string are classified `unverifiable` — the import still runs. Only *positive mismatch* blocks. |
| B5 | Override? | `--force` converts a blocking result into a warning. The same "--force to override" hint is embedded in the blocking message. |
| B6 | Ordering vs. `--dry-run`? | Compat check runs **before** dry-run exits. A blocking dry-run still fails with exit 1 — you can't mask an incompatibility by adding `--dry-run`. |

## Non-goals for v0.4

- Model-level detection (pw5 vs. oasis3). `version.txt` doesn't carry a
  reliable model string across firmware generations; family is enough
  for now.
- Kobo / reMarkable detection paths. Hooks exist (`detectDeviceFamily`
  returns `kobo` / `unknown`) but no Kobo-specific tests yet.
- Typed schemas for `settings.reader.lua` keys. Unrelated concern
  surfaced during v0.3 field testing; tracked for a later version.

## Notes / gotchas

- The detection-failure-is-soft choice means an older firmware without
  `git-rev` (they exist) doesn't brick the import UX. The tradeoff is
  that a manifest with `koreader_version_min: 2099.01` will import
  cleanly on any device where detection can't read a version — users
  who care about that case can pair compat with a pre-import inspect.
- `version.txt` is absent or unreadable on a surprising number of
  test-mount layouts. `detectDeviceFamily` returns `"unknown"` on any
  read/parse failure rather than throwing.
- Family prefix-matching (`kindle-pw5` accepts `kindle`) means authors
  can label precisely without the gate rejecting a close-enough device.
  The inverse — detected family is a prefix of a manifest entry — is
  *not* a match; the manifest side is the more-specific claim.
