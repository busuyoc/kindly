# 40 — v0.2 — `kindly snapshot` / `kindly restore`

v0.1 captures the 180 settings in `settings.reader.lua` declaratively.
That's not enough after a factory reset — it misses user-installed plugins,
user-written patches, and per-book state. v0.2 adds a tarball-level backup
for the things that don't fit a declarative YAML.

## Goal

After a factory reset + fresh KOReader install, restoring a snapshot should
recover: plugins, patches, reading history, custom defaults. The
declarative `kindly.yaml` remains the way to restore the 180 settings keys
(with secret filtering). Snapshot is the "everything else" escape hatch.

## Scope decisions

| # | Question | Decision |
|---|----------|----------|
| A1 | What to include? | `settings.reader.lua`, `.old`, `defaults.custom.lua`, `history.lua`, `patches/`, `plugins/` (whole dir). |
| A2 | Only third-party plugins, or all? | **All.** No reliable marker to distinguish; complexity > disk savings. Users with size concerns can add `--no-plugins` later. |
| A3 | Archive format? | `.tar.gz` via system `tar`. Universal, works on macOS and Kindle-internal shell. |
| A4 | Default output path? | `./kindly-snapshot-<iso>.tar.gz` in cwd. `--output` to override. |
| A5 | Restore merge semantics? | **Replace, not merge.** Extract overwrites file-for-file. No per-file diffs in v0.2 — we'd need schema awareness per plugin. |
| A6 | Safety net on restore? | Take a pre-restore snapshot first (like safe-write for directories). Default on; `--no-safety-snapshot` to skip. Rollback is "extract the pre-restore snapshot". |
| A7 | Secrets in snapshots? | Yes — snapshots are raw copies, including `settings.reader.lua` with secrets. Snapshots are NOT git-safe. Gitignore pattern added; doctor warns. |

## Non-goals for v0.2

- Diffing two snapshots (just use `tar -tf`).
- Incremental snapshots — always full.
- Per-book `.sdr` sidecars (highlights/bookmarks). Big can of worms:
  thousands of files, merge semantics across devices, reading-position
  conflicts. Tracked for a later version.
- Cross-device restore (Kindle snapshot → Kobo) — paths diverge.

## Commands

```
kindly snapshot [--output <path>] [--mount <path>]
kindly restore <archive> [--dry-run] [--no-safety-snapshot] [--mount <path>]
```

## Build order

1. `src/fs/archive.ts` + tests — tar create/extract/list against tmpdirs.
2. `src/commands/snapshot.ts` — list what's present, run tar, report.
3. `src/commands/restore.ts` — pre-snapshot safety copy, extract, report.
4. Wire both into `src/cli.ts`, top-level help.
5. Smoke test against live Kindle (snapshot only — do not restore on live).
6. Update README with the new commands.

## Notes / gotchas

- `parseArgs` in `src/cli/args.ts` treats `--no-<flag>` as "set boolean
  <flag> false" — so a flag *literally named* `no-safety-snapshot` gets
  masked (the parser strips `no-` and then can't find `safety-snapshot`
  in the spec). Fix: name the positive flag (`safety-snapshot`, default
  true) and rely on the `--no-` handler to invert it. Applies to any
  future boolean that we want to default-on.
